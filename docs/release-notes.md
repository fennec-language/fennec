# Release notes

What changes for programs between releases, newest first. A line goes in with the change that makes it.

## Next release

- **`std.pack`: a type that writes its own `serialize` is shaped by what it saves.** A standard library type that saves as another has that type's shape: a `Deque[T]` or `SortedSet[T]` a `list[T]`'s, a `SortedMap[K, V]` a `dict[K, V]`'s, a `Grid[T]` or `Packed[T]` a `list[list[T]]`'s, a `Uuid` or `Time` text's and a `Duration` an int's. A type of a program's or a kit's that writes its own is shaped by its name and type arguments alone. Before, their shapes held their fields, so how std keeps a `Deque` inside, or a field of a type its own `serialize` never saves, changed the hash though the bytes saved were the same. This changes the shape hash of every saved value that holds one of these types, and its `pack.lock` entries. A `Deque`'s bytes are now a list's, and each loads as the other.
- **`std.pack`: a generic type's shape now holds its fields.** The shape a value of `Pair[int]` is saved with was its name and type arguments alone, so moving or changing a field of `Pair[T]` didn't change it. Data saved before such a change then loaded into the wrong fields, with no error. The shape is now its fields' with the arguments filled in, as `Pair[int]{first: int, second: int}`, as a plain struct's always was. This changes the shape hash of every saved value that holds a generic type, and its `pack.lock` entries. Data saved by an earlier release that carries its layout still loads, by its fields' names, as data from another version of a type does.
